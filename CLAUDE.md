# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
./scripts/fetch-dataset.sh          # one-time: clone the 295 MB exercise catalogue
docker compose up --build           # full stack → web :8080, api :3001, db :5433
docker compose down -v              # reset the database completely

cd api  && npm run dev              # API with hot reload (needs db up + env vars, see README)
cd api  && npm run parser:check     # regression-check the PDF parser against 1.pdf and 2.pdf
cd web  && npm run dev              # Vite dev server :5173 (proxies /api and /dataset)
cd web  && npm run build            # typecheck + production build
```

**Docker Desktop is not running on this machine.** Prefix docker commands with
`DOCKER_CONTEXT=default` to use the system daemon, or the socket lookup fails.

`npm run parser:check` is the fastest feedback loop for anything touching parsing — it runs
without Docker or a database.

## Architecture

Three services in `docker-compose.yml`: `db` (Postgres 16), `api` (Fastify + TypeScript),
`web` (Vite build served by nginx, which also proxies `/api` and serves the dataset media).

The exercise catalogue lives in `data/exercises-dataset/` (gitignored, fetched by script) and is
**bind-mounted read-only** into both `api` (reads `exercises.json`) and `web` (nginx serves the
GIFs/thumbnails at `/dataset/...`). Media never passes through the API.

### The PDF parser is the load-bearing piece

`api/src/parser/pdfParser.ts` reconstructs a table from loose positioned text. The source PDFs are
generated by jsPDF and have **no table structure** — only text at coordinates. Three properties of
these files drive the implementation and will silently break the parser if forgotten:

1. **Every string is painted twice** at the same position (jsPDF's fake-bold). Deduplicate by
   `x|y|text` or every value appears doubled.
2. **pdf.js returns whole draw calls**, so `"58 Kg"` arrives as one item. Each item is split on
   whitespace — without this, token classification fails for every cell while
   `tokens.join(' ')` still *looks* correct in debug output.
3. **Grid geometry is measured, not hardcoded** (median gap between date columns / exercise rows),
   so tables with different column counts still parse.

Layout: date columns across the top (`dd/mm/yyyy`), exercise names down the left (`x < firstCol−20`),
and each cell holding weight (`58 Kg` or `11 p.`), reps (`9r` / `8+1r`) and time under tension
(`02' 32"`). The lower ~38 % of each row band is the trainer's marks row, not values.

Domain notes that are easy to get wrong:
- `8+1r` means **8 complete reps + 1 incomplete** → `reps: 8, partial_reps: 1`. Volume uses complete
  reps only.
- Units are **per entry**, not per exercise: `ROTARY Esquerre` uses `p` (plates), everything else `kg`.
- Empty cells (`-`) must be **omitted**, never stored as 0.
- The green/red arrows in the PDF only encode whether weight went up or down, so they are **computed**
  from the previous session (`weightDelta`), never extracted from the images.
- The `AP` / `NS` / `MT` marks are undocumented. They are parsed into `entries.notes` so nothing is
  lost, but are **deliberately not shown anywhere in the UI** — do not invent meanings for them.

### One code path for all data

`api/src/importer.ts` is used by both the initial seed (`seed.ts`, which imports `1.pdf` and `2.pdf`
into the `mama` profile at every boot) and the upload endpoints. Everything is idempotent:
`imports` is unique on `(profile_id, sha256)` and `entries` upserts on `(session_id, exercise_id)`,
so re-importing a PDF changes nothing. Import is two-phase — `preview` computes what *would* change
without writing, then `commit` applies it.

Exercises are a **global catalogue** shared by both profiles; profile ownership comes via
`sessions.profile_id`.

### Matching gym names to the catalogue

`api/src/dataset/match.ts` maps trainer names (Catalan/Spanish, with machine brands like `MEDX`)
onto the English catalogue. Order: a curated table → token scoring with cat/es→en translation and a
bonus for `leverage machine`. Two guards matter: a `NO_MATCH` set for exercises known to have no
equivalent (`ROTARY *` would otherwise match "lever rotary calf", a calf exercise), and a 0.5 score
threshold — an unassigned exercise is better than a wrong GIF, and the UI lets the user pick manually.

### Frontend conventions

- **All user-facing text lives in `web/src/i18n/ca.ts`.** Never inline a Catalan string in a
  component. That file also holds the English→Catalan maps for muscles, equipment, body parts,
  months and weekdays. Exercise names themselves stay as the trainer wrote them.
- **Light theme only.** No dark mode, no system-preference following — the users are 40–50 and the
  brief is a calm, high-contrast white UI. Base font is 17px and all sizing is in `rem` so browser
  text scaling doesn't break the layout. Palette and type scale live in `tailwind.config.js`.
- The accent colour is the CSS variable `--accent`, set from the active profile's `color` column;
  components use `var(--accent)` rather than hardcoding. Profile colours must stay dark enough to
  carry white text (mama `#be185d`, papa `#0369a1`).
- Charts animate **when scrolled into view**, not on mount — `useChartReveal()` gates rendering on
  `useInView`. A chart that looks blank in a screenshot is usually just un-revealed, not broken.
- Exercise cards show the static thumbnail and only swap to the GIF on hover (`ExerciseMedia`) —
  the catalogue is 126 MB of GIFs. Hover is gated on `(hover: hover) and (pointer: fine)`.

### Motion rules (enforced — see the animation skills in `.agents/skills/`)

The motion code was audited against Emil Kowalski's / Apple's standards. Re-introducing any of these
is a regression:

- No `ease-in` on UI, no `transition: all`, no animating layout properties (`width`/`height`/`top`).
  Bars grow with `transform: scaleX()` + `transform-origin: left`, not `width`.
- UI animations stay **under 300ms**; chart reveals are 600ms (explanatory, once per view).
  Tab switching is opacity-only at 150ms — it happens dozens of times a day.
- Enter/exit variants use full `transform` strings (`translateY(8px)`), not Framer's `x`/`y`/`scale`
  shorthands, which aren't hardware-accelerated. **Exception:** `layoutId` elements (nav underline,
  profile pill, metric switcher) are left to Framer — they're already interruptible springs.
- Springs use the Apple form `{ type: 'spring', duration, bounce }`, shared as `SPRING` in
  `web/src/lib/motion.ts`; strong curves `EASE_OUT` / `EASE_IN_OUT` live there too.
- Pressable elements get the `.pressable` class (`scale(0.97)` on `:active`, 160ms).
- `prefers-reduced-motion` keeps opacity/colour transitions and drops movement — it is *not* a
  blanket "all transitions to zero". Handled in `index.css` plus `useReducedMotion()` per component.
